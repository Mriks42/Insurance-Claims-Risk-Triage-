% Abstract
\begin{abstract}
\noindent
We present an end-to-end automotive insurance fraud triage system that combines gradient boosting ensemble models, SHAP explainability, Retrieval-Augmented Generation (RAG), and production engineering practices. The system achieves a Validation PR-AUC of 0.3223 (+28\% over baseline) on the Vehicle Insurance Fraud Detection dataset (15,420 claims, 5.99\% fraud rate), concentrating fraud at 32.5\% in the top 5\% of flagged claims (5.4$\times$ enrichment). The pipeline includes Optuna Bayesian hyperparameter tuning, out-of-fold stacking ensemble, isotonic calibration, fairness analysis using the 80\% disparate impact rule, batch drift monitoring, and temporal performance analysis. A 7-page Streamlit dashboard is deployed live on Hugging Face Spaces via Docker and GitHub Actions CI/CD. All experiments are tracked with MLflow.
\end{abstract}

\section{Introduction}

Insurance fraud costs the U.S. industry an estimated \$40 billion annually. Manual review of every claim is infeasible at scale — insurers need an automated triage system that concentrates investigator effort on the highest-risk claims while approving low-risk claims automatically.

This project builds a complete fraud triage pipeline on the Kaggle Vehicle Insurance Fraud Detection dataset \cite{kaggle}. The system addresses three core challenges: (1) accurate fraud risk scoring on a severely imbalanced dataset (6\% fraud rate), (2) explainable predictions that non-technical investigators can act on, and (3) production-ready deployment with monitoring and fairness guarantees.

A critical finding during development was that the original notebook included \texttt{PolicyNumber} as a model feature — a row identifier with 15,420 unique values across 15,420 rows. This caused artificial PR-AUC inflation from 0.25 to 0.79. All results reported here use the corrected pipeline with \texttt{PolicyNumber} excluded.

\section{Dataset and Feature Engineering}

\subsection{Dataset}
The \texttt{fraud\_oracle.csv} dataset contains 15,420 automotive insurance claims with 33 columns. The target variable \texttt{FraudFound\_P} is binary (0 = legitimate, 1 = fraud) with a 5.99\% fraud rate (923 positive cases). Data is split 80/10/10 stratified by target (train: 12,336 / val: 1,542 / test: 1,542).

\subsection{Feature Engineering}
We engineer 41 new features from the 31 raw columns across six categories:

\begin{enumerate}[leftmargin=*, itemsep=1pt]
    \item \textbf{Ordinal encoding} — 13 string-range columns (e.g., \texttt{"2 to 4"} $\rightarrow$ 3) converted to numeric midpoints
    \item \textbf{Time-based} — \texttt{WeekGap}, circular \texttt{MonthGap}, \texttt{SameDayOfWeek}
    \item \textbf{Binary risk flags} — \texttt{NoPoliceReport}, \texttt{NoWitness}, \texttt{PolicyHolderFault}, \texttt{YoungDriver}, \texttt{WeekendAccident}
    \item \textbf{Interaction features} — \texttt{Age\_x\_Deductible}, \texttt{Fault\_NoPolice}, \texttt{PriceToDeductible}
    \item \textbf{Guideline-grounded flags} — 7 features derived directly from internal fraud guidelines: \texttt{Liability\_NoPolice}, \texttt{HighValue\_Liability}, \texttt{Sport\_YoungDriver}, \texttt{VeryEarlyClaimFlag}, \texttt{EarlyClaimFlag}, \texttt{HighSupplements}, \texttt{ExternalAgent\_NoPolice}
    \item \textbf{Composite} — \texttt{RiskFlagCount} (sum of 14 binary indicators)
\end{enumerate}

The guideline-grounded features are particularly important: \texttt{Liability\_NoPolice} (liability policy + no police report) ranks as the second most important feature by SHAP value (mean $|\text{SHAP}|$ = 0.546), directly reflecting the staged accident profile described in internal fraud documentation.

\section{Modeling}

\subsection{Baseline Models}
We train three baseline models on raw features (no engineering): Logistic Regression, XGBoost, and LightGBM. PR-AUC is used as the primary metric — it is appropriate for imbalanced classification where ROC-AUC can be misleadingly optimistic.

\subsection{Improved Models}
We apply three improvements: (1) Optuna Bayesian TPE hyperparameter search (20 trials, 3-fold CV per trial), (2) CatBoost with native categorical handling, and (3) out-of-fold (OOF) stacking ensemble with XGBoost and CatBoost as base learners and Logistic Regression as the meta-learner.

The best model (XGBoost Optuna) achieves a Test PR-AUC of 0.2443 and Test ROC-AUC of 0.8331 on the completely held-out test set. 5-fold CV PR-AUC is $0.2164 \pm 0.0248$.

\section{Explainability and RAG}

\subsection{SHAP Explainability}
We use \texttt{shap.TreeExplainer} to compute SHAP values for every test claim. Global feature importance is computed as mean $|\text{SHAP}|$ across the test set. The top features are \texttt{Fault} (0.823), \texttt{Liability\_NoPolice} (0.546), \texttt{PolicyHolderFault} (0.246), and \texttt{Fault\_NoPolice} (0.244) — confirming that the guideline-grounded features are among the most predictive.

Per-claim reason codes are generated using longest-prefix matching to correctly decode one-hot encoded feature names containing underscores (e.g., \texttt{AddressChange\_Claim\_2 to 3 years}).

\subsection{RAG Triage Briefs}
The RAG pipeline indexes 4 internal fraud guideline documents (56 chunks) using ChromaDB with \texttt{all-MiniLM-L6-v2} sentence embeddings. For each claim, a retrieval query is built from claim attributes and SHAP reason codes, the top-5 relevant passages are retrieved, and a triage brief is generated using GPT-4o-mini (OpenAI) with citations to the retrieved passages. A structured template fallback operates without an API key.

\section{Fairness, Monitoring, and Temporal Analysis}

\subsection{Fairness Analysis}
We apply the 80\% disparate impact rule — the standard in US insurance regulation — across three protected attributes: age group, sex, and marital status. Groups with fewer than 30 claims are excluded from the calculation to avoid unreliable ratios from sparse samples.

Key finding: the model flags males at $\sim$22\% vs. females at $\sim$12\%, yielding a disparate impact ratio of 0.574 (below the 0.80 threshold). This may reflect genuine fraud patterns in the data or proxy discrimination via correlated features such as \texttt{VehicleCategory} and \texttt{AgentType}, which would require further investigation before production deployment.

\subsection{Model Monitoring}
The test set is split into 6 time-ordered batches to simulate production monitoring. Per-batch statistics (fraud rate, average risk score, SIU fraud rate) are tracked, and feature distribution drift is detected using the Kolmogorov-Smirnov test (with Evidently as an optional enhanced backend). Batch 5 shows drift in 1 of 7 numeric features (14.3\% drift share).

\subsection{Temporal Analysis}
Month-by-month evaluation reveals significant performance variation: PR-AUC ranges from 0.11 (November) to 0.71 (December), suggesting seasonal fraud patterns. Precision@5\% drops to 0 in October and November, indicating months where the model struggles to concentrate fraud at the top of the risk ranking.

\section{Production Engineering}

\subsection{Pipeline and Experiment Tracking}
A single \texttt{train.py} entry point replaces four manual scripts. All settings live in \texttt{training\_config.yaml}. Every run is logged to MLflow with nested runs: \texttt{full\_pipeline} (parent) logs dataset statistics and runtime; \texttt{model\_improvement} (child) logs all model metrics, Optuna parameters, and the best model artifact.

\subsection{Testing and CI/CD}
60+ pytest tests cover feature engineering, data preprocessing, modeling utilities, and the RAG pipeline. Two GitHub Actions workflows run on every push: \texttt{tests.yml} runs the test suite and blocks deployment on failure; \texttt{deploy.yml} pushes the latest code to Hugging Face Spaces.

\subsection{Deployment}
The application is containerized using Docker and deployed to Hugging Face Spaces at \href{https://huggingface.co/spaces/Mriks/fraud-triage}{\texttt{huggingface.co/spaces/Mriks/fraud-triage}}. A lightweight \texttt{Dockerfile.slim} is provided for local testing in disk-constrained environments. The full \texttt{Dockerfile} is used by Hugging Face for live deployment.

\subsection{Dashboard}
A 7-page Streamlit dashboard provides: (1) Summary Dashboard with KPIs and PR curve, (2) Review Queue with ranked claims, (3) Claim Detail with SHAP waterfall and RAG brief, (4) Live Scoring for new claims, (5) Fairness Analysis, (6) Model Monitoring, and (7) Temporal Analysis. Each page includes a collapsible \textbf{ℹ️} explanation panel for non-technical users.

\section{Conclusion}

We present a complete, production-ready fraud triage system that advances beyond standard academic ML pipelines in several dimensions: data leakage detection and correction, guideline-grounded feature engineering, Bayesian hyperparameter optimization, OOF stacking, SHAP explainability with correct OHE decoding, RAG-powered investigation briefs, fairness analysis, drift monitoring, temporal evaluation, MLflow experiment tracking, automated testing, and Docker-based deployment with CI/CD. The system achieves a 5.4$\times$ fraud enrichment in the SIU tier and an estimated \$868,400 net benefit on the test set, demonstrating practical business value alongside technical rigor.
